# Visitplate

Фотоотчёт после выезда - локальное Windows-приложение для техника, монтажника или сервисного инженера. Разложите снимки по узлам, назначьте пары «до/после», запишите выполненное и оставшиеся действия, затем проверьте PDF перед передачей заказчику.

Никаких аккаунтов и облачной обработки. Внутри проекта остаются копии оригиналов, а в PDF попадают отдельные подготовленные изображения. Дату, статус и выводы задаёт человек; приложение не придумывает результат работ.

Версия 0.1.0 - предварительный выпуск для Windows 11 x64. Перед рабочим применением проверьте его на копии своих материалов. Проверка на чистой Windows без установленной среды разработки пока не заявляется.

## Скачать и запустить

В [выпуске 0.1.0](https://github.com/levvs-one/visitplate/releases/tag/v0.1.0) скачайте `Visitplate-0.1.0-windows-x64.zip` и распакуйте **всю** папку. Запускайте `Visitplate.exe` из распакованного каталога, не из окна архива. Среда .NET 10.0.11 включена; отдельно устанавливать SDK для использования приложения не нужно.

Файлы не имеют цифровой подписи издателя. Сверьте SHA-256 архива с `SHA256SUMS.txt` в том же выпуске; это проверяет совпадение скачанного файла, но не заменяет проверку доверия к источнику. Программа не просит отключать защиту Windows и не требует прав администратора.

Храните проекты отдельно от папки программы. Для обновления распакуйте новый выпуск в новый каталог; не заменяйте и не удаляйте рабочую папку выезда. Windows 10, ARM64 и другие версии Windows отдельно не проверены; перечень ОС самой среды .NET доступен в [документации Microsoft](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md).

## Первый отчёт

1. Нажмите «Новый выезд», выберите обычную локальную родительскую папку и новое имя проекта. Заполните название, объект, исполнителя и дату. Появится рабочая папка с `visitplate.json` и `originals`.
2. Добавьте JPEG/PNG и создайте узел, например отдельный прибор или помещение. Выберите снимок в нижней ленте и назначьте его «До», «После» или «Общий вид». Добавьте подписи и свои записи. Поворот на 90° меняет только использование снимка, не исходный файл.
3. Нажмите «Подготовить PDF», проверьте страницы и выберите «Сохранить этот PDF». Сохраните под новым именем вне проекта. Перед отправкой откройте результат в обычном PDF-просмотрщике и проверьте текст и фотографии.

Результат - отдельный фотоотчёт с узлами, парами снимков и заметками. Для его чтения получателю не нужен Visitplate. Папка проекта остаётся у вас для последующих правок.

**Заказчику передавайте PDF, а не всю рабочую папку.** Копии оригиналов сохраняют GPS и другие метаданные камеры. Изображения для PDF создаются заново без исходных EXIF/GPS/XMP и миниатюр, но видимое содержимое фотографии и введённые сведения не обезличиваются. Подробности - в [правилах хранения и приватности](docs/safety.md).

## Частые действия

### Продолжить прошлый выезд

Нажмите «Открыть» и выберите папку, содержащую `visitplate.json`. При открытии проверяются структура проекта и хэши зарегистрированных оригиналов. Изменения сохраняются после паузы; состояние сохранения видно внизу окна. «Сохранить» или `Ctrl+S` запускает явное сохранение. При ошибке не закрывайте окно, пока не сохранили важный текст отдельно.

### Исправить пару или порядок

Выберите узел слева, а затем фотографию в нижней ленте. Назначение нового «До» или «После» заменяет использование после подтверждения. Кнопка «Убрать снимок из узла» оставляет оригинал в проекте. Узлы перемещаются кнопками «Выше»/«Ниже», общие виды - кнопками порядка снимков. Один оригинал нельзя использовать одновременно как «До» и «После» одного узла.

### Внести правку после просмотра

Вернитесь к редактированию, исправьте данные и подготовьте новый PDF. Старый черновик не используется для новой редакции. Сохранение копирует просмотренные байты, а не запускает повторную генерацию. Уже существующий файл не перезаписывается - выберите другое имя.

Вне текстового поля `Ctrl+Z` отменяет до 32 последних изменений структуры и записей; импорт сбрасывает эту историю. В текстовом поле действует обычная отмена WPF. В просмотре `Alt+Left` / `Alt+Right` переключают страницы. Полная проверка клавиатурной доступности текущего интерфейса ещё не завершена.

## Границы

Поддерживаются JPEG и PNG. CMYK отклоняется; для PNG может понадобиться ручной поворот из-за поддержки `eXIf` в Windows. Отдельная gamma/цветность PNG без sRGB или читаемого ICC также отклоняется. Подробные [правила обработки цвета](docs/safety.md#фотографии-цвет-и-приватность) объясняют, как подготовить совместимую копию.

Структурные пределы: 200 оригиналов, 100 узлов, 200 использований снимков, до 50 МиБ на файл и 2 ГиБ зарегистрированных оригиналов. Это не обещание, что любые 200 снимков поместятся в один PDF: действуют дополнительные пределы страниц, текста, производных и доступной памяти. Все значения перечислены в [формате проекта](docs/format.md#численные-пределы).

Работайте на локальном диске вне облачной синхронизации. Сетевые пути, junction, символические ссылки и облачные placeholders не поддерживаются. Приложение не подписывает документ и не подтверждает достоверность даты, фотографий или выполненных работ. PDF/A, PDF/UA, все emoji и все письменности не заявляются.

## Запуск из исходников

Нужны Windows x64, PowerShell и .NET SDK из ветки `10.0.4xx` с WPF. В `global.json` зафиксирован SDK `10.0.400` с `rollForward: latestPatch`: допускается более новый патч этой же ветки, не произвольный SDK 10. Целевой framework приложения - `net10.0-windows`. Core-тесты дополнительно используют Windows API для независимого чтения PDF и не предназначены для Linux/macOS.

Из корня этого проекта:

```powershell
$env:DOTNET_CLI_TELEMETRY_OPTOUT = '1'
$env:DOTNET_GENERATE_ASPNET_CERTIFICATE = 'false'
dotnet restore Visitplate.sln --locked-mode
dotnet build Visitplate.sln -c Release --no-restore
dotnet run --project src\Visitplate.App\Visitplate.App.csproj -c Release --no-build
```

При первом восстановлении зависимостей требуется доступ к NuGet. Не удаляйте lock-файлы, чтобы обойти ошибку locked restore: сначала проверьте SDK и согласованность `csproj` с `packages.lock.json`.

Тесты запускаются отдельно:

```powershell
dotnet test --solution Visitplate.sln -c Release --no-restore
```

Используется Microsoft.Testing.Platform через MSTest.Sdk. Для выбора места синтетических файлов задайте `VISITPLATE_TEST_ROOT` как абсолютный локальный путь; без переменной используется временная папка. Тесты junction используют локальную NTFS-папку. Фотографии тестов синтетические, пользовательские материалы не нужны; часть тестовых результатов намеренно остаётся для осмотра.

В тестах есть все 8 EXIF-ориентаций с 4 ручными поворотами, сохранение исходных байтов, удаление камерных метаданных из производных, конфликты ревизий, запрет перезаписи, отмена и подготовка/чтение настоящего PDF. Наличие этих тестов не заменяет визуальную проверку каждого готового отчёта.

## Если операция не завершилась

- Ошибка с именем фотографии означает, что конкретный файл не принят; прочитайте весь список. Остальные допустимые файлы могут быть импортированы.
- При конфликте редакций откройте проект заново, предварительно сохранив важный несохранённый текст отдельно.
- Если исходник изменён или исчез, восстановите точную копию. Не редактируйте хэш в JSON ради обхода проверки.
- После отмены или ошибки могут остаться `.partial`, черновики и незарегистрированные копии. Они не означают успешное сохранение. [Порядок разбора и восстановления](docs/safety.md#как-действовать-после-ошибки-или-отмены) описан отдельно.

## Устройство и лицензии

`Visitplate.App` - WPF-редактор и CPU-предпросмотр записанного PDF через [PDFiumCore 154.0.8035](https://github.com/Dtronix/PDFiumCore/tree/4a0d6452bed8a5b495ec893861493b521b1e09c2) и PDFium, с показом растровой страницы штатным WPF BitmapSource. `Visitplate.Core` - модель выезда, локальное хранение, нормализация фотографий и PDFsharp/MigraDoc. Встроены два начертания Noto Sans; внешние шрифты при работе не загружаются. Отдельные условия нативных библиотек и их полные тексты включены в [сторонние уведомления](THIRD-PARTY-NOTICES.md).
