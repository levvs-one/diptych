# Формат проекта и API

Visitplate хранит один выезд в обычной папке. Записи и ссылки на снимки находятся в `visitplate.json`, копии фотографий - в `originals`. Проект можно перенести целиком на другой поддерживаемый локальный диск и открыть снова. Абсолютные пути исходных фотографий в JSON не записываются.

Для первого отчёта см. [README](../README.md). Перед переносом или восстановлением прочитайте [правила хранения](safety.md).

## Файлы проекта

```text
Папка выезда/
  visitplate.json
  originals/
    <assetId:N>.jpg
    <assetId:N>.png
    <assetId:N>.jpg.partial
  .visitplate.lock
  visitplate-<revision>-<guid:N>.backup.json
  .visitplate-<guid:N>.partial
  .visitplate-drafts/
    <guid:N>/
      <assetId:N>-<manualQuarterTurns>.jpg
      report.pdf.partial
      report.pdf
```

Не все показанные файлы существуют одновременно. `.partial` означает промежуточный файл, а не готовый результат. `N` в записи GUID означает 32 шестнадцатеричных знака без дефисов. Для оригинала расширение вычисляется по `format`: `jpg` или `png`.

`originalFileName` сохраняет только имя входного файла для отображения. Оно не определяет путь оригинала. Поля `relativePath` в JSON нет; его добавление считается неизвестным полем и отклоняется.

Папка нового проекта сначала создаётся рядом с назначением как `.visitplate-create-<guid:N>.partial`. После проверки JSON она переименовывается в выбранное имя без замены существующего объекта. PDF для передачи сохраняется вне рабочей папки проекта.

## JSON, схема 1

Файл записывается как UTF-8 JSON с именами полей в `camelCase`. Неизвестные и повторяющиеся поля, пропущенные обязательные параметры, недопустимые `null`, повреждённый JSON и глубина больше 16 отклоняются. Перечисления записываются числами, не строковыми именами.

Минимальный пример незаполненного проекта ниже показывает только структуру. Он не является готовым отчётом: для PDF нужны заполненные данные и назначенные фотографии.

```json
{
  "schemaVersion": 1,
  "id": "96d39941-bd14-4450-b9ea-af96e581813a",
  "revision": 0,
  "details": {
    "title": "",
    "site": "",
    "visitDate": "2026-09-05",
    "author": "",
    "customer": null,
    "reference": null
  },
  "assets": [],
  "observations": []
}
```

### VisitDocument

| Поле | Тип и ограничения |
| --- | --- |
| `schemaVersion` | `int`, только `1` |
| `id` | Непустой `Guid` проекта |
| `revision` | `long`, от `0`; успешное сохранение или регистрация фотографий увеличивает на 1 |
| `details` | Объект `VisitDetails`, не `null` |
| `assets` | Массив `PhotoAsset`, до 200 оригиналов |
| `observations` | Массив `Observation`, до 100 узлов; порядок задаёт порядок узлов в PDF |

### VisitDetails

| Поле | Тип и назначение |
| --- | --- |
| `title` | `string`, название отчёта, до 4000 единиц UTF-16 |
| `site` | `string`, объект или место, до 4000 |
| `visitDate` | `DateOnly`, JSON-строка `YYYY-MM-DD`, дата, указанная пользователем |
| `author` | `string`, исполнитель, до 4000 |
| `customer` | Необязательный `string?`, заказчик, до 4000 |
| `reference` | Необязательный `string?`, номер заявки, до 4000 |

### PhotoAsset

| Поле | Тип и ограничения |
| --- | --- |
| `id` | Непустой `Guid`, уникальный среди оригиналов проекта |
| `format` | `PhotoFormat`: `0` = JPEG, `1` = PNG |
| `originalFileName` | Обычное непустое имя файла без пути, до 255 единиц UTF-16 |
| `length` | `long`, точное число байтов скопированного оригинала, больше 0 и не более 50 МиБ |
| `sha256` | SHA-256 всех байтов оригинала, 64 символа `0-9a-f` в нижнем регистре |
| `pixelWidth`, `pixelHeight` | `int`, размеры исходного изображения до EXIF и ручного поворота |
| `exifOrientation` | `int?`, `null` или `1..8`; считывается из JPEG, а не вычисляется по пропорциям |

В C# есть вычисляемое свойство `RelativePath`; оно не сериализуется. Обычное сохранение не может удалять, менять, переставлять или добавлять `assets`. Добавление проходит через импорт и отдельную регистрацию с проверкой копий.

### Observation и PhotoUse

| Поле `Observation` | Тип и назначение |
| --- | --- |
| `id` | Непустой `Guid`, уникальный среди узлов |
| `title` | `string`, название узла, до 4000 единиц UTF-16 |
| `finding` | `string`, наблюдение, до 4000 |
| `workDone` | `string`, выполненные действия, до 4000 |
| `remaining` | `string`, оставшиеся действия, до 4000 |
| `status` | `ObservationStatus`: `0` = Recorded, `1` = Completed, `2` = FollowUp |
| `photos` | Массив `PhotoUse`; суммарно до 200 использований во всём проекте |

| Поле `PhotoUse` | Тип и назначение |
| --- | --- |
| `assetId` | `Guid` уже зарегистрированного оригинала |
| `role` | `PhotoRole`: `0` = Before, `1` = After, `2` = Overview |
| `caption` | `string`, подпись до 400 единиц UTF-16 |
| `manualQuarterTurns` | Необязательный `int`, по умолчанию `0`; значения `0..3` задают поворот на 0°, 90°, 180°, 270° по часовой стрелке после EXIF |

В узле допустимы не более одного снимка «до» и одного «после». Один оригинал нельзя назначить одновременно в обе эти роли внутри одного узла. В разных узлах он может использоваться повторно с разными подписями и поворотами. Удаление использования не удаляет оригинал.

Пара «до/после» выводится первой, затем текстовые записи, затем снимки общего вида в порядке массива. Каждый узел начинается с новой страницы; его номер повторяется в колонтитуле продолжения. Дата выезда и статус не извлекаются из метаданных фотографии.

Незаполненные строки разрешены для редактируемого проекта. Для подготовки PDF отдельно обязательны название отчёта, объект, исполнитель, хотя бы один узел, название каждого узла и хотя бы одна назначенная фотография во всём документе. Отсутствие «после» при наличии «до» даёт предупреждение, а не вымышленный второй снимок.

Все текстовые пределы измеряются `string.Length`, то есть единицами UTF-16, не визуальными знаками. Суммарный предел - 250 000 единиц, включая имена исходных файлов и подписи. Переводы строк и табуляция сохраняются; остальные управляющие символы и повреждённые суррогатные пары отклоняются.

## Численные пределы

| Объект | Предел |
| --- | ---: |
| JSON проекта | 2 МиБ |
| Оригиналы | 200 файлов, суммарно 2 ГиБ |
| Один оригинал | 50 МиБ; 100 000 000 пикселей; до 30 000 пикселей по каждой стороне |
| Узлы / использования фото | 100 / 200 суммарно |
| Миниатюра / выбранное фото | Длинная сторона до 320 / 800 пикселей |
| Производная для PDF | Длинная сторона до 2048 пикселей, JPEG quality 88 |
| Производные одного черновика | Суммарно до 96 МиБ |
| PDF | До 150 страниц и 128 МиБ |

1 МиБ = 1 048 576 байтов; 1 ГиБ = 1 073 741 824 байта. Это условия отклонения, не обещание вместимости или времени обработки. Другой предел, нехватка диска или памяти могут сработать раньше. 2 ГиБ не включает резервные JSON, черновики, незарегистрированные копии и остатки отменённых операций. Проверка размера PDF выполняется после записи промежуточного файла.

## Публичный API Core

Пространство имён - `Visitplate.Core`. Коллекции модели используют `ImmutableArray<T>`; изменение документа создаёт новый объект, например через C# `with`. `default(ImmutableArray<T>)` не заменяет пустой массив.

Ниже приведены сигнатуры, не самостоятельная программа. У всех показанных асинхронных операций `cancellationToken` по умолчанию равен `default`, а `progress` - `null`.

```csharp
Task<VisitProject> VisitProjects.CreateAsync(
    string newDirectory, VisitDetails details, CancellationToken cancellationToken = default);
Task<VisitProject> VisitProjects.OpenAsync(
    string directory, CancellationToken cancellationToken = default);
Task<VisitProject> VisitProjects.SaveAsync(
    VisitProject project, VisitDocument document, CancellationToken cancellationToken = default);

Task<ImportResult> VisitPhotos.ImportAsync(
    VisitProject project, ImmutableArray<string> sourcePaths,
    IProgress<VisitProgress>? progress = null, CancellationToken cancellationToken = default);
Task<BitmapSource> VisitPhotos.LoadPreviewAsync(
    VisitProject project, Guid assetId, int manualQuarterTurns, int maxDimension = 800,
    CancellationToken cancellationToken = default);

ImmutableArray<VisitIssue> VisitReports.Validate(VisitDocument document);
Task<ReportDraft> VisitReports.PrepareAsync(
    VisitProject project, IProgress<VisitProgress>? progress = null,
    CancellationToken cancellationToken = default);
Task<string> VisitReports.PublishAsync(
    VisitProject project, ReportDraft draft, string newPdfPath,
    CancellationToken cancellationToken = default);
```

- `CreateAsync` требует существующую родительскую папку и новое, незанятое имя. `VisitProjects.DocumentFileName` равен `visitplate.json`.
- `OpenAsync` проверяет JSON и длину/SHA-256 всех зарегистрированных оригиналов. Это не повторное декодирование всех изображений.
- `SaveAsync` требует текущие `id`, `revision`, неизменный список оригиналов и совпадение файла проекта с открытым снимком состояния. Возвращает новый `VisitProject`. Не игнорируйте результат: прежний объект становится устаревшим. Эта операция не перечитывает хэши всех оригиналов.
- `ImportAsync` возвращает `ImportResult(Project, Issues)`. При смешанном наборе допустимые файлы регистрируются, остальные получают ошибки с именем файла. Отмена и конфликт регистрации выбрасывают исключение; копии могут остаться незарегистрированными. Исходные файлы не перезаписываются.
- `LoadPreviewAsync` требует `manualQuarterTurns` в `0..3`, `maxDimension` в `1..800`. Возвращает замороженный WPF `BitmapSource`, пригодный для передачи между потоками. Хэш и заголовок оригинала проверяются перед нормализацией. Изображение не увеличивается сверх исходного размера.
- `Validate` не читает файлы. Он возвращает структурные ошибки, недостающие обязательные данные и предупреждение о неполной паре.
- `PrepareAsync` создаёт новый черновик для сохранённой ревизии. Нормализует используемые фотографии, формирует PDF, повторно читает его и сверяет число страниц, затем проверяет используемые оригиналы и текущую ревизию.
- `PublishAsync` копирует именно байты переданного черновика. Требует новое имя `.pdf` вне проекта, существующую локальную папку, ту же ревизию/отпечаток JSON и неизменные использованные оригиналы. Повторной генерации PDF нет. Возвращает путь только после проверенной записи и переименования без замены.

`VisitProject` создаётся библиотекой и содержит `DirectoryPath`, `Document`, `DocumentFingerprint`. Последнее - SHA-256 фактических байтов JSON; даже внешнее изменение пробелов меняет отпечаток.

`ReportDraft` создаётся библиотекой и содержит `Path`, `ProjectId`, `Revision`, `DocumentFingerprint`, `Sha256`, `PageCount`, `PhotoCount`, `Warnings`. `PhotoCount` - число использований снимков, не уникальных файлов. `ReportDraft` не хранится в JSON и не является переносимым разрешением на сохранение другого PDF.

`VisitIssue` содержит `Severity` (`Warning`/`Error`), `Code`, `Message` и необязательные `ObservationId`, `AssetId`, `FileName`. `VisitProgress` содержит `Phase`, `Completed`, необязательные `Total` и `CurrentFileName`. Фазы: `Importing`, `Normalizing`, `Paginating`, `Verifying`, `Publishing`; не каждая операция посылает все фазы. Это прогресс стадий и элементов, не потоковый счётчик байтов.

Основные ошибки передаются через `ArgumentException`, `InvalidDataException`, `IOException`, `UnauthorizedAccessException` и `OperationCanceledException`. Детали восстановления некоторых ошибок доступны в `Exception.Data` как `PartialPath`, `BackupPath` или `DraftDirectory`. Не считайте отсутствие этих ключей доказательством отсутствия промежуточных файлов.

## Изображения и PDF

JPEG и PNG читаются штатными WPF-кодеками. Проверяется соответствие расширения декодируемому формату. Для JPEG учитываются EXIF-ориентации `1..8`, включая зеркальные варианты; затем применяется ручной поворот конкретного использования. Исходные блоки EXIF/GPS/XMP не переносятся в производную. Ограничения PNG, цвета и отмены описаны в [правилах безопасности](safety.md#фотографии-цвет-и-приватность).

Производная создаётся заново из пикселей: Bgr24, 96 DPI, белая подложка прозрачности, без исходных EXIF/GPS/XMP и встроенных миниатюр. Пропорции сохраняются. PDF использует A4 и включённые в приложение Noto Sans Regular/Bold. Если шрифт не содержит нужного знака или библиотека сообщает ошибку изображения, успешный черновик не возвращается. Шрифты встраиваются полными файлами; [версии и хэши](../THIRD-PARTY-NOTICES.md) зафиксированы отдельно.

Перед рисованием проверяется ширина непереносимых фрагментов по реальным метрикам встроенного шрифта. Фрагмент, который не помещается в свою колонку, отклоняется с названием поля и узла: разделите его обычным пробелом или переводом строки. Неразрывный пробел не становится точкой переноса. Программа не сокращает текст, не уменьшает шрифт и не вставляет скрытые разделители.

Фотография с подписью должна целиком помещаться на странице. Высота подписи проверяется отдельной раскладкой MigraDoc с той же шириной колонки, стилями и высотой изображения. Если группа требует второй страницы, перенесите длинное описание в поле наблюдения. Обычный текст узла может продолжаться на следующих страницах; слишком длинная табличная подпись не обрезается молча.

Готовый PDF не заявляется как PDF/A, PDF/UA, подписанный документ или документ с гарантированным отображением всех письменностей. Произвольные внешние PDF не являются входным форматом приложения.
